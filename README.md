# DecisionForge

DecisionForge is a framework for experimenting with, comparing, and combining decision-making models and decision engines.

The initial use case is automated classification of contract documents using multiple engines under comparable conditions.

Current engines:

- StartLux
- Laya
- Jev

The long-term goal is to extend DecisionForge beyond classification toward retrieval, planning, execution, and automated workflow testing.

---

## Architecture

DecisionForge separates application logic from the individual decision engines.

```text
                         DecisionForge
                              │
                ┌─────────────┼─────────────┐
                │             │             │
                ▼             ▼             ▼
            StartLux         Laya           Jev
             local           local          API
                │             │             │
                └─────────────┼─────────────┘
                              │
                              ▼
                     Decision / Classification
                              │
                              ▼
                         Evaluation
```

Optional retrieval:

```text
Document
   │
   ▼
Embedding
   │
   ▼
Vector Store Client
   │
   ▼
Qdrant
```

Qdrant runs independently on an external VPS and is not deployed by this repository.

## Applications

### Document Classification

The first DecisionForge application classifies contract documents into predefined categories.

Example classes:

- NDA
- Service
- Purchase
- License
- Employment
- Lease
- Amendment
- Termination
- Other

The same document and classification criteria can be evaluated against multiple engines.

```text
Contract
   │
   ├── StartLux
   ├── Laya
   └── Jev
        │
        ▼
    Evaluation
```

---

### Testing

The testing application is separate from model benchmarking.

Its purpose is to evaluate whether a system can achieve a defined goal by using DecisionForge components such as the planner and executor.

```text
Test Case
   │
   ▼
Planner
   │
   ▼
Decision Engine
   │
   ▼
Executor
   │
   ▼
Target Application
   │
   ▼
Observation
   │
   └──────► Planner
```

Possible metrics include:

- Goal completion
- Number of steps
- Number of decisions
- Execution failures
- Backtracking
- Total duration
- Decision confidence

## Packages

### Core

Contains common DecisionForge abstractions.

Examples:

```text
DecisionEngine
DecisionRequest
DecisionResult
```

Engine-specific implementations communicate with external services instead of depending on their internal source code.

```text
DecisionEngine
├── StartLuxEngine
├── LayaEngine
└── JevEngine
```

### Planner

Transforms a goal and current state into planned actions or decisions.

### Executor

Executes actions generated by the planner or decision layer.

### Evaluation

Contains reusable evaluation logic for classifications, benchmarks, and testing runs.

## Services

StartLux and Laya are included as Git submodules:

```text
services/
├── StartLux-Decision/
└── laya/
```

DecisionForge therefore pins the exact Git commit of both services.

This keeps desktop and laptop installations on compatible service versions.

Clone with:

```bash
git clone --recurse-submodules <repository-url>
```

For an existing clone:

```bash
git submodule update --init --recursive
```

After pulling changes:

```bash
git pull
git submodule update --init --recursive
```

## Runtime Environments

StartLux and Laya use separate Python environments.

Virtual environments are local and are not committed to Git.

Example:

```text
.venvs/
├── startlux/
└── laya/
```

The environment definitions and setup scripts should remain reproducible across machines.

---

## Desktop and Laptop Configuration

DecisionForge supports different runtime configurations depending on available hardware.

Example:

```text
Desktop PC
├── larger StartLux model
└── optional Laya

Laptop
├── smaller StartLux model
└── optional Laya
```

Both systems use the same repository and pinned service versions.

Docker Compose uses:

```text
infrastructure/compose.yml
```

as the common base configuration.

Device-specific overrides:

```text
infrastructure/compose.pc.yml
infrastructure/compose.laptop.yml
```

Individual engines can be enabled through Compose profiles.

Example:

```bash
docker compose --profile startlux up -d
```

or:

```bash
docker compose --profile laya up -d
```

## Benchmarking

DecisionForge should allow multiple engines to process the same test cases under comparable conditions.

Planned metrics include:

- Accuracy
- Macro F1
- Confusion Matrix
- Confidence
- Calibration
- Brier Score
- Latency
- Cost
- Coverage at confidence thresholds

Example:

```text
contract_001
Ground Truth: NDA

StartLux → NDA
Laya     → NDA
Jev      → Service
```

## Configuration

Runtime endpoints and credentials are configured through environment variables.

Example:

```env
STARTLUX_URL=http://localhost:8090
LAYA_URL=http://localhost:8000

JEV_URL=https://api.typesafe.ai
JEV_API_KEY=

QDRANT_URL=
QDRANT_API_KEY=
```

Secrets must not be committed.

Only example configuration files should be versioned.
